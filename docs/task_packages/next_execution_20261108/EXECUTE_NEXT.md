## 2. 实现单一路径联合候选，禁止只补诊断

复用现有 v5、相对 DAV2、地面标定、SurfaceGrid2D、OccupancyGrid3D 和已有状态语义。
在独立 PC 候选模块/分支实现；不要直接替换 Android 或生产运动授权。

- 从原候选集合中逐个验证同一角度、路径起点、空间范围、当前地图快照和人体通行带。
- 地面候选与障碍净空必须指向最终选中的同一条路径；不能拿左边的地面与右边的净空拼接授权。
- `raycast_clearance(pose, candidate_angle)` 仍会扫邻近角度，不是定向验证。使用明确的单路径查询，返回实际验证的方向和区间。
- 纳入现有人体半径和安全裕量；检查通行带中的地面边界和障碍。不能只用中心射线，也不能把未观测盲区填为 FREE。
- 保留即时人体占用的阻断优先级；缺几何、过期证据和未知区域不产生猜测方向。
- 不是“原两个角度不同就拒绝所有输出”。搜索两层都支持的候选；无共同可行候选时按现有语义拒绝。
- 只做对应定向测试：异向证据、同向证据、前方阻挡/侧边可行、两侧阻挡、窄缝、未知/缺失。不能用合成通过代替真实数据结果。

实现路径扫掠空间检查可参考 Nav2 的路径验证/footprint 代码和契约，不需要新增 ROS 依赖：
https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/bt_plugins/actions/ValidatePath/
https://api.nav2.org/nav2-rolling/html/footprint__collision__checker_8py_source.html
如果摘录源码，保留相应许可和上游版本；本任务不直接要求拷贝上游实现。

1. **接口修复通过**：每个实际授权都有同一路径两层检查，所测反例不再错误拼接。
