## 立即处理的具体代码契约风险

`pc/tools/mobilio_sanpo_ab.py` 独立调用 Surface 与 Occupancy 的方向搜索；`mobilio_occupancy.py::raycast_clearance` 返回它独立选出的 CLEAR 射线；`mobilio_fusion.py::fuse` 对两个 CLEAR 状态选 Surface 的方向，没有要求两份证据指向同一条路径。

本轮已执行原 `fuse` 函数的合成反例：Surface CLEAR 在 0 度、Occupancy CLEAR 在 +30 度，输出仍为 CLEAR/STRAIGHT；Surface CLEAR 在 -30 度、Occupancy CLEAR 在 +30 度，仍输出 CLEAR/LEFT。原源码 Git blob 核对一致：`1a4a63ef1286e8619634ed7129d5999ac25cac85`。

证据：[core_navigation_20261108/evidence.json](../phase_reports/core_navigation_20261108/evidence.json)。复现脚本：`pc/tools/check_route_certificate.py`。这是精确函数反例，不是完整地图回放；不同方向可能都安全，反例证明的是接口没有认证最终选中方向。不能宣称它解释了全部 17 个危险代理放行或当前低覆盖。

## 执行任务：同一路径的地面与障碍联合验证，然后一次真实前后对照

1. **复用已有产物，不先重跑模型。** 从 E3 `on_per_frame.csv.gz` 读取 production/mobilio 的 481 帧，对授权帧的 `surface_angle_rad` 与 `occupancy_angle_rad` 做归一化角差统计。记录不一致的帧键、角度、状态、是否缺失；不要把角差直接计作碰撞。已有真实结果优先交回，不重复运行。
2. **只修这一项接口问题，先在独立 PC 候选中实现。** 沿用原分割、相对 DAV2、地面标定、SurfaceGrid2D、OccupancyGrid3D 和状态语义。对于准备输出的每个候选方向，查询该同一条路径的地面可走证据与障碍净空，再选择两者共同通过的候选。不得拿左边地面证据与右边障碍净空合并授权。
3. `raycast_clearance(pose, candidate_angle)` 仍会扫描邻近方向，**不能**把这个调用当成对指定方向的检验。需有明确的单方向查询/证书；保持原即时人体占用 STOP 优先级。中心射线通过不代表人能通过：应用现有人体半径/安全裕量检验扫掠空间及地面边界，未知或视野不足不能填 FREE。输出实际验证的角度、距离范围和通行带宽度。
4. 不用简单的“角度不同一律拒绝”代替联合候选搜索，那可能只增加 UNKNOWN。也不降低阈值凑覆盖率。没有共同可行候选时按现有规则拒绝，不伪造 LEFT/RIGHT。原生产入口保持不动；离线候选验证前不接入真人运动授权。
5. 仅对本改动做针对性检查（同向、异向、正前阻挡/侧面可行、两侧阻挡、未知区域、窄缝），然后在此前 E3 的同一环境与冻结 481 帧上运行一次候选，对照原始记录。优先使用可核实缓存；必要推理每帧一次，不重复 OFF/ON、不画新展示页、不下载新模型。
6. 输出 `before_after.csv`、逐 session 汇总、方向/净空证书、实际命令/退出码/日志及代码 SHA。模型/深度/几何保持相同才可与历史比较；否则明确差异，不能称单因素修复。必要时在同一顺序回放中共享模型输出给旧/新地图，避免重复推理。
7. 缺原图/权重/标定时一次性报告精确缺项；不要退回到不断写计划。`check_route_certificate.py` 的三例已运行，不要求为了流程重复运行。2×2 保留为后续深度/语义归因工具，不作为这个已定位接口修复的先决条件。

## 两项能力怎么验，不能再用输出数量替代

**直行**：前方走廊方向、横向偏移和保持航向；不是只检测一条图像直线。使用已有路面语义和位姿记录验证直路是否误转、左/右偏移是否反向纠正、原地转手机是否被误认为人偏离。复用 `corridor_truth_eval.py` 的分组/评分逻辑，但参考路径只作为标签或明确标记的外部目标；不能把录制者未来轨迹注入决策后宣称自动发现直线。`mobilio_sanpo_ab.py` 的 `rotation_only=False` 是占位字段，不能据此宣称原地转手机误纠正为 0。

**避障**：分开报告障碍识别、针对所选方向的净空与绕障完成。对真实帧逐项标注前/左/右是否可通行、未知及必须停止，模型输出前固定标注，保留争议/未标注。不用“画面里有危险”的帧标签直接评价左右路径。缺这类标签时，先给方向一致性修复及代理指标，绕障正确率仍不可评；离线录像不能证明接受指令后的真实闭环行走成功。

现有 481 帧是反复使用的开发集，不是独立验收集。开发对照须同时报告可通行帧授权、危险代理授权、UNKNOWN/OBSERVE/STOP 和失败实例；即使前后有改善也不能据此安全认证。之后用独立连续短片检查直行与前方阻挡/左右可行/全阻挡，明确数量和通过条件；不隐藏失败，不用无障碍场景充当绕障测试。

## 固定复用路线与手机终点

- 当前电脑算法链：既有 v5/SegFormer + 相对 DAV2 Small/已有地面标定 + 已移植的 Mobilio-inspired 地面/占据地图，先解决同一路径的证据接法，不重新找十个模型。
- Basalt + TUM VI 是记录位姿的后续替换基线，目前未复现，不作为当前地图接口修复的前置；没有新 VIO 时不能声称手机已具有可靠三维定位。
- 安卓已有 CameraX、ONNX Runtime、语音与传感器壳，但当前 `ObstacleDetector` 是 YOLOv8n、`BlindPathDetector` 是另一个盲道/斑马线 ONNX，并非 PC 的 v5/DAV2/Mobilio 链。电脑合格后，验证同一模型权重、预处理、类别映射、深度单位、坐标和后处理在手机一致；不能把 PC 模型换成另一套再沿用分数。
- 此基线仓库 assets 列表未包含代码所需 ONNX 权重，只能认定仓库没有这些文件，不能推断执行机也没有。执行者检查已有本地资源/打包配置，缺失就报实际阻塞，不默认下载未知权重。
- 最终交付是手机摄像头实时输入、手机端真实推理/反馈的受控原型；手机显示 PC 结果或网页回放不算。断网不影响已要求的本地链路、掉帧/权限/模型缺失时不能产生陈旧运动授权。性能和温升按实际设备报告，不能用 PC FPS 代替。
- 真实行走只能在有视力人员监督的受控场地，不以原型替代盲杖。截止日期不能把无证据的能力写成通过。
