## 3. 当前可用的核心实验基线

### 3.1 Mobilio 生产 D 冻结回放

同一组 481 帧的当前报告统计：

- 最终授权方向：49/481；
- 最终 UNKNOWN：275/481；
- GT danger 帧：295；
- 危险帧上仍出现方向指令：17/295；
- confirmed-clear 帧：150；
- confirmed-clear 上 STOP：0/150。

这些是**决策/授权统计**，不是独立的障碍物检测召回率。LEFT/RIGHT 是否真的避开障碍，还需要路径/轨迹真值。

理想输入 A 条件最终授权也只有 29/481。因此不能把当前低覆盖完全归因于 DAV2 或 VIO；地图搜索契约、Surface/Occupancy 证据和融合规则也需要检查。

### 3.2 E1 逐层矩阵

生产 D 条件：

- Surface：CLEAR 79、OBSERVE 268、UNKNOWN 134；
- Occupancy：CLEAR 180、OBSERVE 35、UNKNOWN 266；
- Fusion UNKNOWN：275；
- 最终授权方向：49。

最终主因计数包括：
- surface:no_candidate_ray：125；

- occupancy:no_fully_observed_clearance：44。

这些跨层原因不是可直接相加的互斥分母。必须保留逐帧和分层矩阵。

### 3.3 E2 Occupancy hint

随包独立复核支持：
- 新增 observation_hint：37；
- hint 出现在 GT danger：19；
- hint 出现在 confirmed-clear：12；
- 最终授权方向仍为 49；
- danger forward-guidance miss 仍为 17/295；
- confirmed-clear false STOP 仍为 0/150。

结论：**诊断信息增加，不代表导航可用性提高。** E2 不得作为导航性能改善宣传。

### 3.4 E3 Surface instrumentation

代码级独立审查认为新增的 termination/last-walkable 字段和单元测试未发现改变状态/授权的副作用。但旧实现对未达到最小候选长度、在候选筛选前被丢弃的射线，仍可能只返回默认 0/None。

最新 E3 任务书已经明确要求先验证旁路 trace 能捕获这些被筛掉的射线，再考虑 481 帧完整重放。**E3 完整回放尚未完成。**

## 4. 近期优先级：只推进一个主线

### P0 收尾：环境与数据校验
- 当前审计主机曾报告约 66 MB 可用磁盘；该快照不应被当成现在仍然准确，执行前必须重新检查。
- 不在有未提交改动的 BlindNav 工作树中安装/构建。
- Basalt 官方 macOS ARM64 二进制路线可以核实，但必须先确认版本、体积、校验值、依赖和磁盘空间；不因“有二进制”就直接安装。
- TUM VI room1 的具体文件 MD5 仍需在下载前确认。

### E3：Surface 射线失败诊断
- 先做小型合成单测，证明所有扫描射线（包括候选筛选前被丢弃的射线）可被旁路捕获。
- 对照 trace OFF/ON 的逐帧 Surface、Occupancy、Fusion、command、authorization，要求完全等价。
- 仅当输入、缓存、模型和标注都齐全时，才重放冻结 481 帧。
- 若缺少原图、v5 checkpoint、DAV2 输出、内参、位姿或地面标定，必须标记 NOT_EVALUABLE/HOLD，不能从旧 CSV 伪造射线记录。

### P1：Basalt + TUM VI
- E3 诊断支线不代表 P1 通过。
- 只有实验环境、官方文件、MD5、许可、标定和 GT 均核验后，才开始一次单序列运行。
- 保存版本、命令、配置、日志、轨迹、有效帧比例、ATE/RPE 和失败记录。

### P2/P3：深度几何与地图
- 复用现有 DAV2 57 帧结果，不重复跑相同实验。
- Metric3D 权重许可、尺度/焦距约定未确认前不下载、不宣称可用。
- 先独立量化深度和几何误差，再把经过验证的输入接入 Harvard/Mobilio 离线地图对照。
- 决策逻辑保持冻结。

## 5. 强制停止条件

出现以下任一情况即 HOLD，不绕过：
1. 原始输入或必要缓存缺失；
2. 数据许可、来源或校验和不清楚；
3. 相机内参、时间戳、坐标系或尺度不一致；
4. trace ON 改变任何安全状态或授权结果；
5. 测试集被用于调参；
6. 指标分母、筛选条件或帧键不一致；
7. 只报告 UNKNOWN/hint/candidate 改善，却没有最终安全与可用性指标；
8. 需要删除用户文件、清理工作树或覆盖历史产物才能继续。

## 6. 后续报告反馈与仓库更新机制

每次收到新报告后，审查者必须：
1. 记录目标分支、实际 commit、文件清单和报告快照；
2. 阅读报告、原始 CSV/JSON、代码差异和独立核查；
3. 区分计划、代码级测试、CSV 重算、完整模型回放、桌面基准和真机实验；
4. 复算关键分子/分母，检查帧键唯一性、条件筛选和 session 分组；
5. 给出 GO / ADJUST / HOLD / STOP；
6. 只在有新证据时新增一份日期化审查记录，或更新本文件的状态表；不覆盖原始实验产物；
7. 只提交审查文档/索引，不修改生产安全策略，不自动合并 PR；
8. 把下一阶段唯一最小实验和可复制执行提示词写入仓库。

报告格式：假设、实际执行、代码/数据版本、结果、分母、证据等级、反证、已证实根因、未证实假设、决策、下一步。
