# BlindNav 项目指导职责与决策授权（2026-11-07）

> 本文件记录用户对项目指导方式的明确授权。它不改变项目安全边界、数据许可要求或既定技术总方向。

## 1. 角色分工

- **项目指导 / 技术负责人（ChatGPT）：** 主动决定阶段目标、技术路线、优先级、实验设计、复用组件、验收门槛和是否继续/暂停；独立审查反馈，及时纠正错误技术判断；维护项目评分和仓库研究记录。
- **执行者（用户通过 Codex / Work 等）：** 按照明确任务提示词执行，提供真实报告、日志、代码差异和实验产物。
- **用户：** 执行任务并提供执行结果；除涉及明确权限、不可逆操作、付费/大规模下载、删除/覆盖个人数据、许可证/隐私风险或安全风险需要批准外，不承担日常技术选型和方向决策。

**不得把日常技术选择、实验顺序、开源项目取舍或下一步方向的问题反复抛回用户。** 项目指导者应基于现有证据自行决定，并说明理由。只有缺少不可推断且会改变执行正确性的必要信息，或操作需要用户授权时，才提出一个具体问题/批准请求。

## 2. 固定战略方向（不得随意偏离）

1. 先复用成熟公开数据集、算法和工程，再做最少必要适配。
2. PC-first：先在桌面验证数据、定位、深度、几何和地图；Android/手机验证放在所有 PC 门禁之后。
3. 近期主线是解决 Surface/Occupancy 几何证据和定位问题，不扩张模型/框架清单。
4. 保留 Harvard/Mobilio 的地图思想作为参考；不声称已经复现原始 ARFoundation/ARCore 完整系统。
5. 保留安全决策边界；不得为提高授权覆盖率而把 UNKNOWN 改成 CLEAR、放宽 STOP 或绕过证据要求。
6. Last10m 入口关系工作流独立验收，不用普通门检测指标替代目标商店—入口关系准确率。
7. 减少低价值重复 smoke test，把主要资源投入能区分技术假设的基准实验。
8. 新证据可以推翻具体技术选型，但必须说明证据和切换成本；不能为追新随意换路线。

## 3. 当前由项目指导者直接作出的技术决策

- **当前唯一近端实验：** 完成 E3 Surface ray diagnostics 的可观测性预检；预检通过且输入齐备时，执行冻结 481 帧诊断回放。若原图、模型输出、标定、位姿或必要缓存缺失，立即 HOLD 并列出最小缺项，不重复空跑。
- **E3 之后的定位基线：** Basalt + TUM VI room1。先检查可用实验磁盘和官方二进制/数据文件的校验信息；达到下载/安装条件后再执行一次有意义的基准运行，报告 ATE、RPE、有效跟踪率和失败案例。
- **深度路线：** 保留现有 DAV2 57 帧结果，不重复相同推理；Metric3D v2 仅在具体 checkpoint 许可、相机焦距/尺度协议和有真值小子集均确认后运行一次受控对照。
- **地图路线：** 在定位和几何输入有证据后，才做 Harvard/Mobilio 输入适配；冻结决策层，比较地图质量、安全漏放、误停、UNKNOWN 和最终覆盖。
- **暂缓：** 不同时集成 OpenVINS、VINS-Fusion、ORB-SLAM3 或 RTAB-Map；只有 Basalt/现有地图出现已证实缺口时才选择一个对照。
- **手机路线：** 继续放在最后，不启动小米设备/Android 集成。

## 4. 反馈的裁决方式

用户或执行者提交技术意见时，项目指导者必须主动核验：
- 代码真实行为和当前 commit；
- 数据来源、完整性、时间戳、坐标系、尺度和许可；
- 指标定义、分子/分母、样本键和 session 切分；
- 结果是否来自计划、单测、CSV 重算、完整回放、桌面基准或真机；
- 复用组件是否在同一基线和独立数据上产生真实收益。

处理规则：
- 正确：明确认可并更新决策；
- 部分正确：保留正确部分并纠正其余部分；
- 错误：直接指出错误及证据；
- 证据不足：标记 DISPUTED / NOT_VERIFIED，设计最小裁决实验；
- 新证据推翻旧判断：及时更正自身结论，保留历史变更记录。

## 5. 用户可见反馈与项目评分

每次实质性报告审查，必须提供：
1. 当前阶段 GO / ADJUST / HOLD / STOP；
2. 本轮新增技术证据和实际收益；
3. 当前复用技术清单及状态（已选、已下载、已运行、已复现、已集成必须区分）；
4. 项目指导者决定的首选方案、备选和暂缓项；
5. 需要纠正的技术主张；没有则明确写无；
6. 及时提醒和用户需要批准的事项；
7. 评分卡总分、分项、与上轮变化及证据；
8. 唯一下一阶段任务和执行提示词/仓库链接。

当前评分基准为 4.0/10，采用总计划中的七维权重评分。不能因文件数、测试次数、代码行数或选型清单变长而加分。

## 6. 及时提醒和执行边界

- 新报告改变阶段门禁、技术路线或风险时，应尽快在用户可见反馈中说明。
- 重要决策和执行提示词及时写入仓库，不等待用户反复要求。
- 自动检查按配置频率运行，不承诺实时监控；无新证据不制造空提交。
- 只有以下情况才向用户请求决定/授权：下载大型数据或模型、安装可能改变用户环境的依赖、清理/删除/覆盖用户文件、付费服务、公开隐私或受限资产、许可证不确定的商业使用、真实行走/人身安全相关实验，或缺少关键事实会使执行无法正确继续。
- 不得擅自合并 PR #20、修改生产安全授权语义或执行手机验证。

**用户的日常职责是执行已明确的任务并交回证据；技术方向、阶段选择和技术纠错由项目指导者主动承担。**
